# QQ 邮箱接入 Dots：踩坑与排障线索

供 Agent 根据实际错误选择排查方向。下表来自 [接入实录](../AGENT-GUIDE.md)，各项修复有自己的前提，无需每次接入都执行全部操作。

| 现象 | 先确认 | 处理边界 |
| --- | --- | --- |
| Codex 成功，Dots 不可用 | 两端的认证、工具列表与执行位置 | Codex 配置不自动同步到 Dots 云端 |
| 上传插件后要求桌面执行器 | `requires_local_executor` 和实际工具类型 | 不能靠修改标记让本地代码成为云服务 |
| 表单没有 API-key 选项 | 当前账号实际可见选项 | 选择受支持 OAuth 入口，不以 None 暴露邮箱 |
| `Client Not Registered` | CIMD 元数据请求是否成功、是否合法 | 双方支持 DCR 时切换客户端注册方式，保留 PKCE/回调限制 |
| 回调拒绝 | 哪一段 OAuth、实际 `redirect_uri`、issuer | GitHub 的回调到网关；网关的回调到客户端；不混用 |
| GitHub 登录正常但访问邮件 401 | 数字 ID、已验证 token 的 subject/sub | 登录成功不等于授权；不删除 owner 检查 |
| 网页成功，云端交换超时 | 同一个容器、HTTP 库、DNS、代理与请求阶段 | 浏览器、宿主 curl 和容器的网络证据分别记录 |
| 宿主 curl 超时，容器请求有 HTTP 响应 | 运行进程实际使用的 HTTP 客户端 | GET token endpoint 的 404 仅证明本次有响应；授权码 POST 成功才证明交换可用 |
| QQ 验证提示过期或请求失败 | 实际发起流程、会话、时间和网络 | 由用户重新完成需要的验证；不要连续索取短信/授权码或绕过验证 |
| GitHub 授权按钮禁用 | 页面真实焦点、可见性、按钮完整可见、正常延时 | 聚焦并等待正常控件可用；不删除 disabled 或伪造页面安全状态 |
| 重启后要求再次登录 | 状态挂载、写权限、稳定签名密钥 | 修正持久化，不公开缓存，不关闭认证 |
| TLS 已登记但仍异常 | 当前活跃服务器、DNS、证书和代理加载结果 | 仅在确认失败阶段后调用平台支持的重新验证/签发 |

## 本次排障留下的操作提醒

- GitHub 授权按钮受真实焦点、可见性和正常延时影响；先观察实际状态，不移除页面自身的限制。
- 浏览器、宿主 curl 和容器 HTTP 库可能走不同网络路径；保存各自结果，固定 IP 或全局代理切换不作为默认答案。
- 隐藏 dialog 和失效的快照 ref 曾造成误判；等待可见状态，并在页面变化后更新定位。
- 临时镜像传输采用仅绑定 loopback 的接收器和 SSH 隧道，结束后清理；已有应用、配置和服务先检查能否复用，避免重复创建或影响其它站点。

这些提醒用于识别相似问题。新任务中的账户验证、工具权限、网络和部署操作仍按当前环境及用户授权处理。
