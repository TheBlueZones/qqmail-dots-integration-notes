# QQ 邮箱接入 Dots：本次验收依据与复用检查

供 Agent 复核结果时参考；结合 [接入实录](../AGENT-GUIDE.md) 中的版本和范围判断哪些检查适用。

每层单独记录结果，不用下一层的推测补齐证据。

| 层 | 最小证据 | 不能推出 |
| --- | --- | --- |
| 配置 | 正确 origin、精确回调、版本和 Secret 注入 | 服务正在运行 |
| 网关 | HTTPS、`/healthz`、OAuth 元数据、无效凭据拒绝 | 邮箱登录正常 |
| 邮箱后端 | `initialize`、只读 `tools/list`、普通邮件读取 | Dots 已连接 |
| 客户端授权 | DCR/CIMD 成功、GitHub 公开身份、owner 校验 | 目标 Dots 实际调用 |
| Dots | 现有目标会话发出请求并返回指定邮件内容；关联可用调用/服务端证据 | 未读状态保持 |
| 副作用 | 同一 `UIDVALIDITY + UID` 前后 FLAGS，无 `\Seen` 新增 | 高并发或附件性能 |
| 重启 | 网关重启后，原授权下再次调用成功 | 永久有效或无限扩容 |

## 复用时如何重做只读验证

1. 检查后端工具集确实不含发送、移动、删除或修改标志的工具。源码只读承诺仍需实际工具枚举核对。
2. 不带令牌、错误令牌访问受保护 `/mcp` 应被拒绝。用合成身份或用户明确提供的测试账户检查非 owner 拒绝；不登录别人的账号。
3. 选定一封用户允许读取的普通未读邮件。记录账户范围、mailbox、UIDVALIDITY、UID 和 FLAGS，不记录整封正文或密码。
4. 从用户指定的 Dots 会话发起一次请求；不把 Codex 或另一条临时聊天的结果当作 Dots 结果。如果 UI 不暴露完整调用记录，可结合相同时间段的网关请求与指定邮件结果说明证据边界。
5. 通过 IMAP 独立复查同一邮件 FLAGS。只读打开 mailbox；正文读取使用 `BODY.PEEK`，不使用“修改回未读”补救。
6. 在任务已覆盖的部署/重启范围内检查持久化：重启该网关，然后验证原授权仍可调用，并检查资源占用、OOM/重启计数和既有站点。若不在授权范围内，单列“重启恢复待验收”，不因此重启无关服务。

推荐的用户请求模板：

> 请用已连接的 QQ 邮箱工具读取我指定的这封普通邮件，仅返回主题、发件人和简短摘要，不读取其它邮件，不发送、删除或修改状态。

如果工具不可见，先核对会话、插件启用状态及客户端范围；明确标记“接入已授权，目标会话读取待验收”，不要编造调用或邮件内容。

## 本仓库测试覆盖

`tests/test_gateway.py` 使用合成身份和隔离 HTTP 响应，覆盖空 scope、owner 双重匹配、密钥/配置校验、后端请求头隔离、加密存储重建、非 owner HTTP 拒绝、刷新令牌轮转及元数据。

测试通过不等于真实提供方互通、地域可达、邮件副作用检查或负载测试。升级库、改变回调、增加工具或调整存储后，重新执行对应层的验证。
